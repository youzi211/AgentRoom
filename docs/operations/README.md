# 运维指南\n\n> 本文档提供 AgentRoom 的生产运维注意事项，包括灰度发布、回滚策略和迁移指南。\n\n---\n\n## 目录\n\n- [灰度发布](#灰度发布)\n- [回滚策略](#回滚策略)\n- [协作运行时迁移](#协作运行时迁移)\n- [安全注意事项](#安全注意事项)\n- [监控与健康检查](#监控与健康检查)\n\n---\n\n## 灰度发布\n\n### 协作运行时灰度\n\n建议按以下顺序逐步启用新协作运行时：\n\n1. 设置环境变量限制：\n   `nv\n   COLLABORATION_ENGINE_ALLOWLIST=native\n   COLLABORATION_DEFAULT_TRIGGER_MODE=mention_only\n   `\n2. 启用远程 Native 房间，观察运行情况\n3. 确认稳定后，开放 AutoGen 引擎：\n   `nv\n   COLLABORATION_ENGINE_ALLOWLIST=native,autogen\n   COLLABORATION_AUTOGEN_ENABLED=true\n   `\n\n### 模型 Profile 灰度\n\n- 先在 Go 或 DeepAgent 运行时中创建测试 Profile\n- 绑定到单个 Agent 进行验证\n- 确认无误后再设为默认 Profile\n\n---\n\n## 回滚策略\n\n### 协作运行时回滚\n\n1. 禁用 AutoGen：COLLABORATION_AUTOGEN_ENABLED=false\n2. 将房间切换回远程 Native\n3. 如果 Python Collaboration Runtime 不可用，设置：COLLABORATION_RUNTIME_MODE=legacy\n\n**重要规则**：\n- 不要回放已到达终态或可能已开始模型调用的运行记录\n- 回滚后旧 dialogue_runs 保持可读，新协作使用 collaboration_runs\n\n---\n\n## 协作运行时迁移\n\n迁移期间：\n- 旧 dialogue_runs 保持可读用于历史查看\n- 新远程协作使用 collaboration_runs + 每轮 gent_runs\n- 仅在灰度观察期被接受后才停止写入新的 dialogue_runs\n\n### 环境变量清理\n\n确认数据库默认值验证通过后，从环境变量中移除旧的迁移兜底：\n- LLM_*（Go 运行时）\n- MODEL_*（DeepAgent 运行时）\n\n---\n\n## 安全注意事项\n\n### 密钥管理\n\n- MODEL_CONFIG_ENCRYPTION_KEY 必须备份并纳入部署 Secret Store\n- 所有后端实例必须使用相同的密钥值\n- 丢失或更改密钥会导致已加密的 API Key 无法解密\n- Profile API Key 使用 AES-256-GCM 加密后写入 MySQL\n- 管理 API 永不返回明文或可识别密文\n\n### WebSocket 安全\n\n- 生产环境必须配置 ALLOWED_ORIGINS\n- WebSocket CheckOrigin 仅在该变量非空时生效\n\n### 管理 API 安全\n\n- 生产环境必须设置 ADMIN_API_KEY\n- 空值会放行所有管理操作，仅适合本地开发\n- VITE_ADMIN_API_KEY 会进入浏览器 bundle，不能承担公网鉴权\n\n### 其他风险\n\n- 当前没有正式用户体系，房间加入以 query name 区分用户\n- 缺少消息发送失败重试与幂等机制\n- 单实例内存 Hub 不能支持多后端实例广播\n- Agent 执行使用有界队列（容量 64，4 worker），但任务不持久化\n\n---\n\n## 监控与健康检查\n\n| 端点 | 说明 |\n|------|------|\n| /api/health | Go 进程存活检查 |\n| /api/ready | MySQL 和 Agent Runtime 依赖就绪检查 |\n| /api/admin/collaboration-runtime | 协作运行时模式、引擎和就绪状态 |\n\n---\n\n## 相关文档\n\n- [部署指南](../deployment/)\n- [架构文档](../architecture/)\n- [协作运行时基线](../architecture/collaboration-runtime-baseline.md)\n
