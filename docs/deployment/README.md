# 部署指南\n\n> 本文档提供 AgentRoom 的详细部署说明，包括 Docker 一键启动、生产环境部署、WSL 配置和加密密钥管理。\n\n---\n\n## 目录\n\n- [一键 Docker 启动](#一键-docker-启动)\n- [环境变量说明](#环境变量说明)\n- [加密密钥管理](#加密密钥管理)\n- [生产环境部署](#生产环境部署)\n- [WSL 特殊说明](#wsl-特殊说明)\n- [Docker Compose 服务](#docker-compose-服务)\n\n---\n\n## 一键 Docker 启动\n\n### 前置条件\n\n- Docker + Docker Compose v2\n\n### 启动\n\n`ash\ngit clone <your-repo-url>\ncd agentRoom_test\ncp .env.example .env\nbash ./scripts/docker-up.sh\n`\n\nPowerShell：\n\n`powershell\npowershell -ExecutionPolicy Bypass -File .\scripts\docker-up.ps1\n`\n\n启动脚本自动完成：\n\n1. 复制 .env.example 到 .env（如不存在）\n2. 替换占位密钥为生成值：ADMIN_API_KEY、VITE_ADMIN_API_KEY、MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD\n3. 生成 MODEL_CONFIG_ENCRYPTION_KEY（32 字节随机 base64 编码）\n4. 对齐 VITE_ADMIN_API_KEY 与 ADMIN_API_KEY\n5. 清理 LLM_API_KEY 占位符\n6. 合并 PUBLIC_ORIGIN 到 ALLOWED_ORIGINS\n7. 执行 docker compose up -d --build\n8. 等待所有服务就绪后打印访问地址\n\n### 停止\n\n`ash\ndocker compose down\n`\n\n### 访问\n\n默认端口：\n- 前端：http://localhost:5173\n- 后端健康检查：http://localhost:8080/api/health\n\n---\n\n## 环境变量说明\n\n| 变量 | 必需 | 默认值 | 说明 |\n|------|------|--------|------|\n| PORT | 否 | 8080 | HTTP 端口 |\n| MYSQL_DSN | 是 | - | MySQL DSN |\n| DB_AUTO_MIGRATE | 否 | false | 是否自动迁移数据库 |\n| MODEL_CONFIG_ENCRYPTION_KEY | 保存模型密钥时必需 | - | base64 编码的 32 字节主密钥 |\n| LLM_BASE_URL / LLM_API_KEY / LLM_MODEL | 否 | - | 迁移期 Go 运行时兜底 |\n| MODEL_BASE_URL / MODEL_API_KEY / MODEL_NAME | 否 | - | 迁移期 DeepAgent 兜底 |\n| TAVILY_API_KEY | DeepAgent 研究时必需 | - | 搜索凭据 |\n| DEEPAGENT_WORKDIR | 否 | ../deepagent | Python 项目目录 |\n| LOG_LEVEL | 否 | info | 日志级别 |\n| LOG_FORMAT | 否 | text | text 或 json |\n| LOG_ADD_SOURCE | 否 | false | 是否输出源码位置 |\n\n### 端口冲突处理\n\n如果默认端口已被占用，在 .env 中设置：\n\n`nv\nFRONTEND_HOST_PORT=5177\nBACKEND_HOST_PORT=8654\nMYSQL_HOST_PORT=13306\n`\n\n### PUBLIC_ORIGIN\n\n生产环境必须设置，用于浏览器访问和 WebSocket 连接：\n\n`nv\nPUBLIC_ORIGIN=http://203.0.113.10:5173\nPUBLIC_ORIGIN=https://agentroom.example.com\nPUBLIC_ORIGIN=https://agentroom.example.com,http://203.0.113.10:5173\n`\n\n---\n\n## 加密密钥管理\n\nMODEL_CONFIG_ENCRYPTION_KEY 是服务端主密钥，用于加密存储在 MySQL 中的模型 API Key。\n\n### 手动生成\n\nPowerShell：\n\n`powershell\n = [byte[]]::new(32)\n[Security.Cryptography.RandomNumberGenerator]::Fill()\n[Convert]::ToBase64String()\n`\n\nBash：\n\n`ash\nopenssl rand -base64 32\n`\n\n### 重要规则\n\n- 必须备份此密钥，放入部署 Secret Store\n- 所有后端实例必须使用相同的密钥\n- 丢失或更改密钥会导致已加密的 API Key 无法解密，需重新录入所有受影响的 Profile\n- 应用不会在 Profile 解密失败时降级到其他凭据\n\n---\n\n## 生产环境部署\n\n### 推荐流程\n\n1. 在部署前生成 MODEL_CONFIG_ENCRYPTION_KEY 并存入 Secret Store\n2. 设置 PUBLIC_ORIGIN 为实际域名或 IP\n3. 配置 ALLOWED_ORIGINS 为实际前端来源\n4. 确保 ADMIN_API_KEY 已设置（空值放行所有管理操作，仅适合本地开发）\n5. 配置 MYSQL_DSN 指向生产数据库\n\n### 安全注意事项\n\n- WebSocket CheckOrigin 仅在 ALLOWED_ORIGINS 非空时生效；生产必须配置\n- VITE_ADMIN_API_KEY 会进入浏览器 bundle，不能承担公网鉴权\n- 当前没有正式用户体系，房间加入以 query name 区分用户\n- DeepAgent 子进程不是安全沙箱，必须按高权限可信代码管理\n\n---\n\n## WSL 特殊说明\n\n在 WSL2 上运行 Docker 时，localhost 转发可能不稳定。启动脚本会自动检测并打印 WSL 直连 IP：\n\n`\nFrontend (direct IP): http://<wsl-ip>:5173\nBackend health (direct IP): http://<wsl-ip>:8080/api/health\n`\n\n前端 Origin 已自动加入 ALLOWED_ORIGINS，WebSocket 通过直连 IP 也可正常工作。\n\nBash 脚本默认启动 WSL 保活进程，防止 Docker 因 WSL 空闲而停止：\n\n`ash\n# 跳过保活\nKEEP_WSL_ALIVE=0 bash ./scripts/docker-up.sh\n\n# 手动停止保活\npkill -f wsl-keepalive.sh\n`\n\n---\n\n## Docker Compose 服务\n\n| 服务 | 说明 | 端口
